# Frontend / backend integration

Checked on 2026-11-07 against `cmd/api/main.go`, the HTTP registrars in `internal/`, and `docs/api/openapi.yaml` (the repository has no `openapi.yml`). The pipeline-progress wildcard was fixed in backend source; the OpenAPI contract was not changed.

## Transport

The browser calls same-origin `/v1/...` using the shared `apiRequest` client with `credentials: include` and `cache: no-store`. Next.js rewrites requests to the server-only `API_URL` origin: development defaults to `http://127.0.0.1:8080`, production to `http://api:8080`. The origin excludes `/v1`. No session secret or API credential is exposed through `NEXT_PUBLIC_*`, localStorage, or component props. Existing HttpOnly session cookies and backend role checks remain authoritative.

Errors support both Problem Details (`detail`, `code`) and the existing `{error: {code, message}}` envelope. Failed writes retain form values and allow retry. Session errors offer sign-in recovery without interpreting every fail-closed JOB response as an expired session. Existing validation is preserved; generic backend validation errors remain form-level when no field is identified.

## Live verification

Docker Compose ran the frontend, API, and worker against disposable PostgreSQL with the branch migrations. Application, assessment, and pipeline-progress routes use the same Gin wildcard, `:application_id`. The regression test registers the real handlers in both orders.

Requests through the frontend proxy verified API readiness, candidate feed, company posting management and preview, candidate application submission and duplicate rejection, application history and details, assessment instance and result reads, logout, and session invalidation. The smoke test used seeded sessions and a screened-out application. It did not exercise browser login, a populated pipeline, SMTP delivery, or Judge0 grading.
